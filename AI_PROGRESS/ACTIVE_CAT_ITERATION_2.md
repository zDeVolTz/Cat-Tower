# Active Cat — Iteration 2: One-Shot Trajectory Shapes

## Что изменено

`ActiveCatSystem.js` был переписан, но **только форма вертикальной кривой полёта**.
Пять spatial-концептов из Iteration 1 (`getTowerExclusionZone`, `getActiveFlightZone`,
`getVisibleGameplayZone`, `getPhantomTrajectory`, camera-isolation) не тронуты —
их публичные сигнатуры и семантика идентичны прежним. One-shot жизненный цикл
(phantom entry → visible flight → TAP → fall → landing, или → exit при промахе,
без автовозврата) тоже не менялся — он уже был реализован верно в Iteration 1.

Горизонтальное движение осталось линейным (X = phantom→phantom интерполяция) —
это сознательное решение, чтобы не жертвовать читаемостью "один чистый выстрел",
ради которой строилась spatial-модель. Характер траектории выражается через
вертикальную кривую (и для diagonal — через асимметричный тайминг подъёма/спуска).

## Три реализованных траектории

Тип фиксируется один раз при спавне (`mover.trajectoryType`), не меняется в полёте.

- **`high_arc`** — симметричная парабола на всю высоту flight zone: вход/выход у
  пола зоны, пик у потолка (t≈0.5).
- **`low_arc`** — симметричная парабола, но зажатая в нижней части зоны: пик
  доходит только до `LOW_ARC_PEAK_FRACTION` (0.55) высоты, никогда не приближается
  к потолку.
- **`diagonal_arc`** — асимметричная: пик смещён (`DIAGONAL_PEAK_T` = 0.32, не 0.5)
  **и** вход/выход на разных высотах (входит низко, выходит высоко, или наоборот —
  зеркалируется по стороне спавна). Собрана из двух независимых квадратичных
  сегментов (подъём и спуск), которые делят только точку пика — поэтому не
  читается как сдвинутая симметричная парабола.

Все три нормализуются относительно одного и того же `getActiveFlightZone()`, так
что форма может влиять только на то, как используется доступная высота, но не
может вывести кота за пределы зоны.

## Выбор типа траектории при спавне

- **По умолчанию `TEST_MODE = "cycle"`** — циклический перебор через
  `ACTIVE_CAT_TRAJECTORY.TRAJECTORY_ORDER = ["high_arc", "low_arc", "diagonal_arc"]`,
  каждый следующий кот — следующий тип по кругу. Это по прямой просьбе для
  плейтеста — чтобы все три типа гарантированно были видны подряд, без ожидания
  случайности.
- `ActiveCatSystem.setTrajectoryTypeMode('random')` переключает на равновероятный
  случайный выбор (для финальной сборки после того как выбран победивший тип/микс).

## TAP momentum — теперь зависит от фазы

Раньше `vx` при отпускании вычислялся как константа из наклона линейного пути
(не зависел от того, когда именно нажат TAP). Теперь `computeReleaseMomentum`
берёт **реальную мгновенную скорость** (finite difference за последний кадр) —
и `vx`, и `vy` — в момент TAP. Для `diagonal_arc`, где вертикальная скорость
сильно меняется по ходу полёта, ранний и поздний TAP теперь дают заметно разный
результат (проверено тестом `RM01`).

## Известные ограничения

- X всё ещё строго линеен для всех трёх типов — только Y даёт характер. Если
  после плейтеста захочется более выраженной "непохожести" по горизонтали
  (не только по вертикали), это отдельная, более крупная правка.
- `diagonal_arc` пик всегда идёт к потолку зоны (frac=0) — не варьируется по
  высоте пика отдельно от асимметрии тайминга. Можно параметризовать отдельно,
  если понадобится больше разнообразия внутри самого diagonal-класса.
- Предсуществующий тестовый долг в `test_jenga_physics.js` (J002-J004) не
  затронут и не исправлен — вне рамок этой задачи.
